## 1. Цель

Переносимое ядро на C11 без единой строки WinAPI. Оно должно:
1. разбирать формулу `f(x)` в дерево выражения и сообщать об ошибках с позицией;
2. вычислять дерево для любого `x` с контролем области определения;
3. интегрировать методами трапеций и Симпсона — с фиксированным `n` или до точности `ε` по правилу Рунге;
4. читать и записывать файл исходных данных `*.txt`;
5. работать из консоли (`integ_cli`), пока нет оконного интерфейса.

Всё проверено автоматическими тестами, собирается и gcc (Linux), и MinGW-w64 (Windows `.exe`).

**Не входит в Ф1:** окна (Ф3–Ф4), HTML-отчёт (Ф4), справка (Ф5).

## 2. Принятые решения уровня кода

| ID | Решение | Обоснование |
|---|---|---|
| Р1-01 | Стандарт **C11**, флаги `-Wall -Wextra -Wpedantic -Werror` | Ловим ошибки на этапе компиляции (совет методички 3.8) |
| Р1-02 | Строки ядра — **UTF-8 `char`**. Перевод в `wchar_t` делает только слой интерфейса | Формула — ASCII, ядро остаётся переносимым и тестируемым на Linux |
| Р1-03 | Ядро **не открывает файлы само**: разбирает текст из буфера (`taskfile_parse(const char*)`). Чтение файла — в CLI и в интерфейсе (`_wfopen` для кириллических путей) | Тесты без файлов. Кириллица в путях решается в одном месте |
| Р1-04 | Ошибки — **код + структура контекста** (`TErrInfo`: код, позиция в формуле, номер строки файла, значение `x`), а не `exit()` и не `printf` | В C нет исключений (Т-22). Интерфейс сам решает, как показать ошибку |
| Р1-05 | Тексты сообщений — **в одном модуле** `messages.c` (таблица «код → текст») | Т-23 |
| Р1-06 | Венгерская нотация: `dbl` — double, `n` — int, `psz` — строка, `p` — указатель, `b` — флаг, `e` — перечисление; типы — `T…`, константы — `MAX_…` | Т-20, совпадает со стилем WinAPI |
| Р1-07 | Модуль ≤ 250 строк, у каждой функции — комментарий о назначении | Т-21 |
| Р1-08 | Симпсон при нечётном `n` — **не ошибка**: ядро берёт `n + 1` и ставит флаг `bNAdjusted` (интерфейс выводит предупреждение) | Удобно пользователю, честно отражено в результате |
| Р1-09 | Предел удвоения `MAX_N = 2²⁰ = 1 048 576` разбиений | Расчёт ≤ ~0,1 с. Если точность не достигнута — флаг `bConverged = false`, а не зависание |
| Р1-10 | Свой мини-фреймворк тестов `tests/test.h` (макросы `CHECK`, `CHECK_NEAR`) + CTest | Без внешних зависимостей, понятно на защите |

### 3.1 `messages.h`
```c
typedef enum {
    ERR_OK = 0,
    /* лексика и синтаксис формулы */
    ERR_BAD_CHAR, ERR_BAD_NUMBER, ERR_UNKNOWN_IDENT, ERR_EXPECTED_OPERAND,
    ERR_EXPECTED_RPAREN, ERR_EXPECTED_LPAREN, ERR_UNEXPECTED_TOKEN, ERR_EMPTY_EXPR,
    ERR_NO_X,                       /* в формуле нет переменной x (предупреждение) */
    /* вычисление */
    ERR_DIV_ZERO, ERR_LN_DOMAIN, ERR_SQRT_DOMAIN, ERR_ASIN_DOMAIN, ERR_TG_POLE,
    ERR_POW_DOMAIN, ERR_NOT_FINITE,
    /* интегрирование */
    ERR_BAD_N, ERR_BAD_EPS, ERR_BAD_LIMITS,
    /* файл исходных данных */
    ERR_FILE_EMPTY, ERR_FILE_SYNTAX, ERR_FILE_UNKNOWN_KEY, ERR_FILE_DUP_KEY,
    ERR_FILE_MISSING_KEY, ERR_FILE_BAD_VALUE, ERR_OUT_OF_MEMORY
} TErrCode;

typedef struct {
    TErrCode eCode;
    int      nPos;      /* позиция в формуле, с 1; 0 — не применимо */
    int      nLine;     /* строка входного файла, с 1; 0 — не применимо */
    double   dblX;      /* x, при котором ошибка вычисления */
    char     szDetail[64]; /* имя функции, ключа и т.п. */
} TErrInfo;

const char *msg_text(TErrCode eCode);                         /* шаблон сообщения */
void        msg_format(const TErrInfo *pErr, char *pszBuf, size_t nSize); /* готовая фраза */
```
Пример готовых фраз: «Ожидается ")" в позиции 6», «Неизвестное имя "sn" в позиции 1», «ln: аргумент должен быть > 0 (x = -0.5)», «Строка 3: неизвестный ключ "mehtod"».

### 3.2 `lexer.h`
```c
typedef enum { TK_NUMBER, TK_X, TK_CONST, TK_FUNC, TK_PLUS, TK_MINUS, TK_MUL,
               TK_DIV, TK_POW, TK_LPAREN, TK_RPAREN, TK_END, TK_ERROR } TTokenType;
typedef struct { TTokenType eType; int nPos; int nLen; double dblValue; int nId; } TToken;
typedef struct { const char *pszSrc; int nPos; TToken tkCur; } TLexer;

void lex_init(TLexer *pLex, const char *pszSrc);
int  lex_next(TLexer *pLex, TErrInfo *pErr);    /* 0 — ок, иначе код ошибки */
```
- Пробелы пропускаются; имена — без учёта регистра (`SIN`, `Sin`, `sin`).
- Число: `12`, `1.5`, `1,5`, `2e-3`, `.5` запрещено (как в БНФ). Разбор числа — свой, через `strtod` на нормализованной копии (запятая → точка), чтобы не зависеть от локали.
- `e` после цифр — экспонента, только если дальше цифра или знак с цифрой; иначе `2e` → ошибка «ожидается оператор».
- Таблицы зарезервированных слов: функции `sin cos tg ctg arcsin arccos arctg exp ln lg sqrt abs`, константы `pi e`.

### 3.3 `ast.h` / `parser.h`
```c
typedef enum { ND_NUM, ND_X, ND_NEG, ND_ADD, ND_SUB, ND_MUL, ND_DIV, ND_POW, ND_FUNC } TNodeKind;
typedef struct TNode { TNodeKind eKind; double dblValue; int nFunc; int nPos;
                       struct TNode *pLeft, *pRight; } TNode;

int  parse_expr(const char *pszExpr, TNode **ppRoot, TErrInfo *pErr);
void ast_free(TNode *pNode);
int  ast_uses_x(const TNode *pNode);
```
Функции разбора соответствуют правилам БНФ из `PLAN.md` §5.2 один к одному: `ParseExpression → ParseTerm → ParseFactor → ParsePower → ParseBase`. Это прямо ложится на блок-схемы раздела 2.3 ПЗ. Константы `pi`, `e` сворачиваются в `ND_NUM` при разборе. При ошибке уже построенные узлы освобождаются — без утечек.

### 3.4 `eval.h`
```c
int eval_node(const TNode *pNode, double dblX, double *pdblResult, TErrInfo *pErr);
```
Проверки области определения: деление на 0; `ln`, `lg` при аргументе ≤ 0; `sqrt` < 0; `arcsin`, `arccos` вне [−1; 1]; `tg`, `ctg` у полюса (|cos| < 1e-12 и т.п.); `a^b` при a < 0 и нецелом b; любой не конечный результат → `ERR_NOT_FINITE`. В ошибку пишется текущий `x`.

### 3.5 `integrate.h`
```c
typedef enum { METHOD_TRAPEZOID, METHOD_SIMPSON, METHOD_BOTH } TMethod;

typedef struct {
    double dblA, dblB;
    int    nN;          /* число разбиений (начальное при адаптации) */
    double dblEps;      /* 0 — фиксированное n; > 0 — подбор n по Рунге */
} TIntParams;

typedef struct { int nN; double dblValue; double dblErrEst; } TIntStep; /* строка таблицы сходимости */

typedef struct {
    TMethod eMethod;
    double  dblValue;     /* значение интеграла */
    int     nN;           /* итоговое n */
    double  dblH;         /* итоговый шаг */
    double  dblErrEst;    /* оценка погрешности по Рунге (NAN, если не считалась) */
    long    nEvals;       /* число вычислений f(x) */
    double  dblTimeMs;    /* время расчёта */
    int     bConverged;   /* достигнута ли eps */
    int     bNAdjusted;   /* n увеличено до чётного (Симпсон) */
    int     nSteps;       /* таблица сходимости */
    TIntStep aSteps[21];
} TIntResult;

int integrate(const TNode *pFunc, const TIntParams *pPar, TMethod eMethod,
              TIntResult *pRes, TErrInfo *pErr);
```
- **Трапеции:** `I = h·[(f₀ + fₙ)/2 + Σᵢ₌₁ⁿ⁻¹ fᵢ]`. При удвоении `n` новая сумма = старая + значения только в новых серединах: вдвое меньше вычислений `f`.
- **Симпсон:** `I = h/3·[f₀ + 4Σf_нечёт + 2Σf_чёт + fₙ]`.
- **Адаптация:** `n₀ = max(nN, 2)` → считать `Iₙ`, `I₂ₙ` → `R = |I₂ₙ − Iₙ| / (2ᵖ − 1)`, `p = 2 | 4` → пока `R > ε` и `n < MAX_N`: удваивать. Каждый шаг пишется в `aSteps` — это таблица сходимости для формы и HTML.
- `a > b` — формулы работают с отрицательным `h`; `a = b` → 0 без вычислений; `n < 1` или `n > MAX_N`, `eps < 0` → ошибка.
- `METHOD_BOTH` интерфейс выполняет двумя вызовами — ядро остаётся простым.
- Время — `clock()` (в Windows точности достаточно для миллисекунд).

### 3.6 `taskfile.h`
```c
typedef struct {
    char    szFunc[256];
    double  dblA, dblB;
    TMethod eMethod;
    int     nN;
    double  dblEps;   /* 0 — не задано */
} TTask;

int  taskfile_parse(const char *pszText, TTask *pTask, TErrInfo *pErr);
int  taskfile_write(const TTask *pTask, char *pszBuf, size_t nSize); /* для «Сохранить данные» */
```
- Формат — `PLAN.md` §5.1: `key = value`, `#` — комментарий, пустые строки пропускаются, ключи без учёта регистра, BOM UTF-8 пропускается, `\r\n` и `\n`.
- Обязательные ключи: `function`, `a`, `b`. По умолчанию: `method = simpson`, `n = 100`, `eps` — не задан.
- Ошибки с номером строки: неизвестный ключ, повтор ключа, нет `=`, неверное число, отсутствует обязательный ключ, пустой файл.
- Формулу при чтении файла сразу проверяем парсером → ошибка «Строка 2: …позиция 6…».

### 3.7 `integ_cli` — консольная обвязка
```text

integ_cli "x^2" 0 1 --method both --eps 1e-8
```
Печатает: формулу, пределы, метод, I, n, h, оценку погрешности, число вычислений, время, таблицу сходимости. Нужна для отладки, для демонстрации ядра на КТ 19.10, если интерфейс будет ещё сырым, и для скриншотов в ПЗ.

## 4. Тесты (критерий готовности ядра)

| Набор | Что проверяем | Примеры |
|---|---|---|
| `test_lexer` | все типы лексем, регистр, числа с `.` и `,`, экспонента, позиции, ошибки | `"2,5e-3*X"` → NUMBER(0.0025) MUL X; `"2e"` → ошибка; `"@"` → `ERR_BAD_CHAR`, поз. 1 |
| `test_parser` | приоритеты и ассоциативность, унарный минус, скобки, ошибки с позицией | `2+3*4 = 14`; `2^3^2 = 512`; `-2^2 = -4`; `(1+2)*3 = 9`; `sin(x` → «ожидается ")"», поз. 6; `sn(x)` → неизвестное имя, поз. 1; `sqrt(x)sin(x)` → неожиданная лексема, поз. 8; `""` → пустое выражение |
| `test_eval` | функции и константы, область определения | `sin(pi/2) = 1`; `ln(e) = 1`; `lg(100) = 2`; `ln(x)` при x = −0,5 → `ERR_LN_DOMAIN`, x записан; `1/x` при 0 → `ERR_DIV_ZERO`; `(-8)^(1/3)` → `ERR_POW_DOMAIN` |
| `test_integrate` | эталонные интегралы, порядки точности, адаптация, крайние случаи | см. таблицу ниже |
| `test_taskfile` | корректные файлы, умолчания, все ошибки с номером строки, BOM, CRLF, запись → чтение (round-trip) | |

**Эталонные интегралы:**

| f(x) | [a; b] | Точное значение | Проверка |
|---|---|---|---|
| `x^2` | [0; 1] | 1/3 | Симпсон точен при любом чётном `n` |
| `x^3 - 2*x + 1` | [−1; 2] | 3,75 | Симпсон точен (кубическая функция) |
| `sin(x)` | [0; pi] | 2 | оба метода, `ε = 1e-8` → \|I − 2\| < 1e-8 |
| `ln(x)` | [1; e] | 1 | |
| `4/(1+x^2)` | [0; 1] | π | |
| `exp(-x^2)` | [0; 2] | 0,882081390762422 | |
| `20*sin(sqrt(x)*3)` | [0; 10] | эталон считаем Симпсоном при `n = 2²⁰` и сверяем с независимым расчётом (Python, mpmath) | функция из примечания к заданию |
| `x` | [5; 5] | 0 | `a = b` |
| `x` | [1; 0] | −0,5 | `a > b` |
| `1/x` | [−1; 1] | — | ошибка `ERR_DIV_ZERO` при x = 0 |

**Порядки точности:** для `exp(-x^2)` отношение ошибок `err(n)/err(2n)` ≈ 4 у трапеций и ≈ 16 у Симпсона (допуск ±10 %). Это экспериментальное подтверждение теории для раздела 1.1 ПЗ.

**Качество:**
- все тесты проходят под **AddressSanitizer + UBSan** (`-fsanitize=address,undefined`) — нет утечек и неопределённого поведения;
- каждый `.c` ≤ 250 строк (проверяет скрипт `tools/check_lines.sh`);
- сборка MinGW-w64 без предупреждений: `integ_cli.exe` и тесты собираются (запуск тестов `.exe` — у вас на Windows или через Wine, если удастся поставить).

## 9. Риски фазы

| Риск | Мера |
|---|---|
| Локаль ломает разбор чисел (`strtod` и запятая) | Свой нормализатор: запятая → точка, `strtod` на копии в «C»-локали |
| Порог полюса `tg` ложно срабатывает или пропускает | Проверка по \|cos(arg)\| < 1e-12 + общий контроль `isfinite` результата |
| Wine недоступен — тесты `.exe` не запустить в облаке | Логику проверяем на Linux. `.exe` — только сборка, запуск — у Артёма |
| Модуль `parser.c` выйдет за 250 строк | Вынести таблицы имён функций и констант в `lexer.c` / отдельный `names.c` |
