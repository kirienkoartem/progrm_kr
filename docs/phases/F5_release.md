# Ф5. Справка, доводка интерфейса, релизная сборка — план и итоги

> **Статус: ✅ выполнено (05.10.2026)** в ветке `f5`. Итоги — в конце файла.

> Ветка `f5` (поверх `f4`). `main` и `kt/19.10` не меняются до решения Артёма.

## Цель

Довести программу до состояния «сдаю на CD»: полноценная справка о работе с программой (требование преподавателя),
аккуратные мелочи интерфейса, устойчивость к сбоям, релизная сборка и структура диска.

## Задачи

| # | Задача | Зачем |
|---|---|---|
| 1 | Справка вынесена в отдельный текстовый ресурс с простой разметкой (заголовки, списки); 10 разделов, включая «Окна программы» и «Сообщения об ошибках» | Требование «справка, как работать с программой»; текст правится без перекомпиляции кода |
| 2 | Поиск по справке и подсветка найденного | Быстро найти нужное |
| 3 | Контекстная справка по F1: раздел зависит от активного окна и поля (формула, метод, график) | Стандартное поведение Windows-программ |
| 4 | Подсказки-заглушки в пустых полях («например, 20*sin(sqrt(x)*3)», «не задана»), подсказка в пустой области результатов, значение интеграла в заголовке графика | Понятность без чтения справки |
| 5 | Перехват непредвиденных ошибок: сообщение вместо аварийного закрытия | Программа не «падает» на защите |
| 6 | Сведения о сборке: версия 1.0, автор, вуз — видны в свойствах `Integral.exe` | Аккуратность продукта |
| 7 | Релизная сборка и структура CD: `Программа/`, `Примеры данных/`, `Исходный код/`, `Пояснительная записка/`, `ПРОЧТИ.txt`; скрипты `tools/make_dist.sh` и `build.bat` | Требование сдачи «файлы проекта + exe на CD/DVD» |

## Готово, когда

- [x] Справка: 10 разделов, поиск, F1 открывает нужный раздел.
- [x] Подсказки в полях и пустых областях.
- [x] Непредвиденная ошибка показывает сообщение, программа продолжает работу.
- [x] `tools/make_dist.sh` собирает папку диска и архив; программа из архива запускается.
- [x] Тесты зелёные, сборка без предупреждений, файлы кода ≤ 250 строк.

## Итоги

- **Справка** вынесена в ресурс `src/Integral.App/Resources/Help.txt` (10 разделов: назначение, начало работы, окна программы, запись формулы,
  методы и точность, формат файла, график, отчёт, сообщения об ошибках, горячие клавиши). Разметка: подзаголовки, списки, примеры моноширинным шрифтом.
- **Поиск по справке**: список разделов фильтруется по введённому тексту, найденное подсвечивается (на Windows).
- **Контекстная справка F1**: из поля формулы или пределов — «Запись формулы», из метода, n, ε — «Методы и точность», из окна графика — «График», без окон — «Начало работы».
- **Подсказки**: серый текст в пустых полях формулы и ε (Windows), подсказка в пустой области результатов, значение интеграла в заголовке графика,
  подсказка в строке состояния «Нет открытых расчётов: Ctrl+N или Ctrl+O».
- **Перехват непредвиденных ошибок**: сообщение вместо аварийного закрытия.
- **Сведения о сборке**: версия 1.0.0, продукт, автор, вуз — в свойствах `Integral.exe`.
- **Диск**: `tools/make_dist.sh` → `dist/КР_Интегрирование_Кириенко_БИ-25/` (Программа, Примеры данных, Исходный код, Пояснительная записка, ПРОЧТИ.txt) и zip-архив;
  `build.bat` — сборка на Windows одной командой.
- **Примеры данных**: добавлены `pi_trapezoid.txt` (видны узлы трапеций) и `gauss_both.txt` (Симпсону хватает n = 64, трапециям нужно n = 2048 при ε = 10⁻⁸).

### Найденная по ходу ошибка (исправлена во всех ветках)

Проект `Integral.App` **не был добавлен в решение `Integral.sln`** с Ф3: команда `dotnet sln add` тогда завершилась ошибкой, это осталось незамеченным.
Сборка решения пропускала оконную программу, а в Visual Studio решение открывалось без неё. Исправлено отдельным коммитом и перенесено в `kt/19.10`, `main`, `f4`.
Вывод на будущее: после изменения состава решения проверять, что `dotnet build` выводит строку `Integral.App -> …Integral.exe`.
